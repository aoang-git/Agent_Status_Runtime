截至统计窗口末，脚本读到 1237 条事实广播，队列累计淘汰 1122 条。这里的淘汰是有界近期缓存按保留规则清理，不等同于已连接的 SSE 消费者丢失广播。

CPU 根据相邻采样的进程 CPU 时间增量除以墙钟时长和逻辑处理器数计算；表中平均是采样值的算术平均，不是时间加权平均。采样约每 63 秒一次，不能捕获所有瞬时峰值。工作集与私有字节含义不同，不能只以工作集代表全部内存使用。

这组样本未显示队列持续增长或后期句柄持续累积，但不能据此排除内存泄漏或证明长期稳定。尚无大量来源、高频工具调用、多消费者或慢消费者的资源基准，也没有实测端到端延迟的 P95/P99；本表不包含测试窗口、安装器或其它 Agent 的资源消耗。

## 轻量运行机制

文件通知合并后按变化来源增量读取，定期检查已知来源，并低频发现新目录；健康接口读取当前诊断，SSE 用共享队列和唤醒机制等待新增记录，不让每个消费者轮询数据库。

活动数据不持久化，核心不会随着运行时长持续积累活动数据库。有界并不意味着整个进程只占 8 MiB：采集上下文、解析器、HTTP 连接、Go 堆和运行时本身还需要内存。

| 数据 | 默认边界 |
|---|---|
| 近期广播队列 | 4096 条、8 MiB、10 分钟，任一条件到达即淘汰 |
| 外部事件去重 | 10000 条、10 分钟 |
| 外部序号流 | 4096 个、闲置 1 小时淘汰 |
| 文件采集上下文 | 4096 个来源、失效 1 小时淘汰 |
| 工具解析关联 | 每来源最多 1024 项，超限标记关联不完整 |
| 诊断日志 | 最多两份，每份 1 MiB |

缓存超限会淘汰或降级；被淘汰来源重新接入时建立基线，不补播遗漏记录。启动基线和发现扫描仍可能因既有记录数量、文件大小、磁盘速度而增加开销，来源上限不是吞吐量承诺。

## 复测方法

在仓库根目录先完成核心构建，再运行：

```powershell
./scripts/soak.ps1 -Hours 72 -OutputDirectory ./.runtime/qa/soak-72h
```

不要同时使用同一个输出目录启动两次测试。脚本使用独立 Runtime、动态回环端口和构造记录；文件超过 1 MiB 会截断重建，避免负载文件无限增长。输出目录必须位于仓库 .runtime/qa 内。

- status.json：开始时间、目标时长、运行状态、当前 PID 和最新样本。
- samples.csv：CPU、工作集、私有字节、句柄、广播数、队列和扫描时间序列。
- synthetic-sessions：人工来源记录。
- runtime：该测试独立的连接发现和诊断目录。

脚本会检查广播持续到达、扫描继续推进、队列不超过条数/字节边界，失败会记录失败状态。运行期间不要原位构建覆盖 bin/agent-statusd.exe，也不要清理本次输出目录；否则会打断样本连续性。

本次阶段性原始记录位于本机 .runtime/qa/soak-72h，运行数据受 .gitignore 排除，不作为安装包或仓库附件。上面的固定统计窗口用于避免后续采样改变文档所述结果；后续完整结果应另行核验后更新。
