# v0.3 接入协议

面向客户端和插件开发者。入门及状态映射见 [插件开发](插件开发.md)，运行参数见 [运行与开发](运行与开发.md)。以仓库的 [JSON Schema](../runtime/internal/monitor/protocol/schema.json) 和 [协议样本](../runtime/internal/monitor/protocol/samples.json) 为准；不提供旧协议兼容。

## 边界与发现

Runtime 只处理服务运行期间新观察到的记录。每次启动生成新 epoch；没有活动数据库、历史恢复或离线补报。文件记录是观察事实，插件记录是状态声明，客户端决定显示。

运行目录 private/connection.json 供只读客户端使用，private/ingest.json 供插件上报使用。结构为 {url,token,pid,epoch}，每次启动原子更新。使用 Authorization: Bearer token；不将令牌放入 URL、日志或 UI。发现文件是实例位置，不代表旧 PID 仍存活；连接后核对 /v3/info 的 epoch。

## HTTP

| 方法与路径 | 内容 |
|---|---|
| GET /v3/info | version、schema=3、epoch、mode=facts、容量限制 |
| GET /v3/schema | JSON Schema，根定义为外部状态上报 |
| GET /v3/health | roots、sources、watcher、started_at、last_scan_at、scan_milliseconds、capacity_exceeded、queue |
| GET /v3/capabilities | 内置四类来源的支持范围及限制 |
| GET /v3/recent | {schema,epoch,revision,facts,dropped}，仅近期诊断 |
| GET /v3/events | 仅订阅边界之后的 SSE |
| POST /v3/ingest | 外部标准状态上报，独立写令牌 |

只读令牌不能写入，写入令牌不能读取。非空 Origin 被拒绝。不支持旧版本端点、Last-Event-ID 或 after 历史续传。

## 外部状态输入

必填：schema=3、producer_id、event_id、agent、session_id、state、reported_basis。
可选：session_namespace、operation_id、occurred_at、native_type、native_reason、stream_id、source_sequence。未知字段、重复字段、控制字符和原始嵌套正文被拒绝，单次最多 16 KiB，标识字符串最多 256 字符。

state: working / tool_activity / waiting_confirmation / idle / completed / interrupted / failed / unknown。
working、tool_activity、waiting_confirmation、completed、interrupted、failed 必须携带 operation_id；同轮稳定不变。session_namespace 缺省 producer_id。

reported_basis: native_event / inferred / self_report。native_event 表示插件依据原生回调；核心不独立验证。不得仅凭消息结束或工具失败声称任务完成。idle 仅代表空闲。

stream_id 和 source_sequence 同时提供或省略。序号仅检测本次运行近期流的缺口，不决定接收新旧。插件应按发生顺序串行发送，不补发离线历史。重复发送使用同一 event_id；真实活动进展使用新 ID；单纯定时存活不得续期。

返回 {schema,id,epoch,duplicate}：201 已进入本次运行内存队列；200 短期重复并返回原 ID；409 同 ID 不同内容。400 非法输入、401 凭据失效、403 权限不匹配、413 超限、415 非 JSON。失败不得阻塞 Agent，发送总预算 1 秒，最多一次重试；401 重读发现文件。

## 统一广播

外部输入规范化为 kind=state.reported、data.state；文件侧广播 session.observed、input.observed、message.observed、tool.observed、approval.observed、lifecycle.observed 和 source.health。保留 agent、命名空间、会话、operation、producer/event ID、原生类型、来源和依据；不含业务正文。

每条记录携带 schema=3、id、received_at、origin=file|external、source_id，必要时 sequence_gap=true。historical 在广播中固定 false；基线及明确继承的记录不广播。occurred_at 只作参考，接收 ID 决定顺序。

## SSE 与缺口

首帧 ready，数据 {schema,epoch,revision}，id 为 epoch:revision；该边界原子建立，不发送既有活动。
后续 fact 数据为新增记录；每 15 秒发送注释心跳。
消费者超过有界缓冲范围时发送 gap（同边界结构），跳至最新位置；客户端清除显示轮次，等待后续活动。慢写超时 5 秒后关闭连接。服务重启或断连后重新发现、重新订阅，不恢复任务或计时。
recent 不能作为完整日志，也不能推进实时游标或生成结束通知。

## 限制及客户端规则

核心缓存：事实 4096 条 / 8 MiB / 10 分钟，去重 10000 条 / 10 分钟，流 4096 个 / 闲置 1 小时，文件来源 4096 个 / 失效 1 小时，工具关联每来源 1024 项。触及任何边界即可淘汰或降级，不能将缺失记录当作成功。
JSONL 单行 8 MiB、压缩读取 16 MiB、解压帧 32 MiB；半行半帧不提前发布。

测试窗口不代表核心裁决：所有来源严格最新优先；同轮计时连续；文件消息静默 3 秒推断；无进展普通 5 分钟、审批 30 分钟超时；结束通知 10 秒。未知、健康和心跳不续期，推断结束不撤回。其它客户端可以采用自己的规则。
