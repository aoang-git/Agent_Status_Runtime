# 其它 Agent 状态上报插件开发

本页适用于当前 schema 3。协议字段的最终定义见 [接入协议](接入协议.md) 和 [JSON Schema](../runtime/internal/monitor/protocol/schema.json)，合法/非法输入及显示案例见 [samples.json](../runtime/internal/monitor/protocol/samples.json)、[interpretation.json](../runtime/internal/monitor/protocol/interpretation.json)。

## 接入边界

插件位于 Agent 的扩展/Hook 环境中，负责理解原生生命周期并输出标准状态。核心不安装、发现、加载、执行或更新插件，只校验输入、标记来源、短期去重并广播。当前仓库不附带某种 Agent 的成品 Hook 插件。

接入前确认具体工具、版本、扩展机制和事件含义。优先选择确定性原生回调，不依赖模型在提示词中“记得上报”。模型自述只能标为 self_report；自行推断必须标为 inferred，不能伪称原生事件。

数据流为：原生回调 → 插件映射标准状态 → CLI 或本机 HTTP 上报 → 核心 state.reported 广播 → 客户端直接采用状态。文件监测仍输出观察事实，由客户端解释，两条路径可以同时存在。

## 状态映射与轮次

| 状态 | 应表达的含义 |
|---|---|
| working | 开始运行或出现真实工作进展 |
| tool_activity | 工具活动；工具结果返回后不自动代表任务完成 |
| waiting_confirmation | 确实暂停等待人工审批或确认 |
| idle | 当前空闲，不等同于成功结束 |
| completed | 本轮明确成功结束，并且不会继续自动处理 |
| interrupted | 本轮被取消或中断 |
| failed | 本轮最终失败；不是一次工具调用失败 |
| unknown | 依据不足，不能确认当前状态 |

开始一轮时生成 operation_id，工作、并行工具、重试及审批切换始终使用同一个 ID。原生没有轮次 ID 时，由插件每轮生成一次，不要每条事件重新生成。明确关闭后若继续工作，开始新轮次。

插件需自行管理并行工具和自动重试；单个工具结束、消息结束或模型暂时停顿，不能直接映射 completed。不同工具的原生“结束”事件可能只结束一步，须核对是否还会自动继续。没有可靠结束边界时报告 unknown，将无进展的保底处理留给客户端。

同一 working 或 tool_activity 可以在真实进展时再次报告，使用新 event_id。单纯定时存活、健康检查和未知不能冒充进展刷新活动超时。

## 输入字段

外部输入直接使用顶层 state，不能提交旧版 kind/data 结构或文件原始事实。

| 字段 | 要求 |
|---|---|
| schema | 必填，固定为数字 3 |
| producer_id | 必填，插件实例/来源标识；重试时保持一致 |
| event_id | 必填，每条真实变化唯一；同一次发送的重试保持一致 |
| agent | 必填，供消费者识别工具来源的稳定名称 |
| session_id | 必填，工具原生会话标识；不要发送目录路径或正文 |
| session_namespace | 可选，缺省 producer_id；用于区分会话标识域 |
| operation_id | working、tool_activity、waiting_confirmation、completed、interrupted、failed 必填；同轮稳定 |
| state | 必填，采用上表中的一个值 |
| reported_basis | 必填，native_event、inferred 或 self_report |
| occurred_at | 可选，RFC 3339 原生发生时间，仅供参考，不决定先后 |
| native_type / native_reason | 可选，原生事件名及脱敏原因代码；不能携带异常堆栈、消息或工具结果 |
| stream_id / source_sequence | 可选，必须一起提供；序号为非负整数，用于检查流缺口，不用于跨来源排序 |

请求最多 16 KiB，标识字符串最多 256 字符。未知字段、重复字段、控制字符和原始嵌套内容会被拒绝。不要发送提示词、工具名称参数组合、输出内容或令牌。完整限制以 Schema 和核心校验为准。

producer_id、agent、session_namespace、session_id 应稳定。只有能确认与文件侧完全相同的会话和轮次身份时才关联；无法确认时使用独立命名空间，不按目录或名称相近猜测关联。

所有来源严格按核心接收序号处理；发生时间和 reported_basis 不改变优先级。插件 completed 之后到达的有效文件活动仍可使客户端开始新轮次，插件不能锁住来源。

## 方式一：调用内置 CLI

优先复用核心的 report 命令，不另写凭据处理和网络重试。以下 PowerShell 7 示例向已安装的 Runtime 提交一条人工工作状态；请在调试时运行，不要把它接入真实 Agent 来代替原生回调：

```powershell
$runtime = Join-Path $env:LOCALAPPDATA 'Programs/AgentStatusRuntime/agent-statusd.exe'
$event = @{
    schema = 3
    producer_id = 'example-hook'
    event_id = [guid]::NewGuid().ToString()
    agent = 'example-agent'
    session_id = 'demo-session'
    operation_id = 'demo-run-1'
    state = 'working'
    reported_basis = 'self_report'
}
$json = $event | ConvertTo-Json -Compress
$json | & $runtime report --validate-only
$json | & $runtime report --best-effort
```

使用自定义运行目录时增加 `--data-dir PATH`。validate-only 不连接服务；best-effort 成功 stdout 为空，失败只向 stderr 写脱敏错误代码并正常退出。普通 report 成功输出 ACK，失败非零退出。

CLI 发送网络总预算为 1 秒，最多一次重试；每次读取当前 ingest.json，401 后重新读取凭据。插件还应为子进程设置总调用时限，避免环境故障阻塞 Agent；参数通过参数数组传递，不拼接 shell 命令，不把 ACK 输出混入 Agent 的 Hook 协议流。

## 方式二：直接 HTTP

无需 Go SDK。按以下步骤实现：

1. 从运行目录 private/ingest.json 读取 url、token、pid、epoch。Windows 默认运行目录为 APPDATA 下 AgentStatusRuntime，读取用户与核心运行用户必须一致。
2. 校验 url 为 HTTP 字面量回环 IP，无用户名、查询串和片段，基础路径为空或 /。关闭代理和自动重定向，不在 URL 中放 token。
3. 向 /v3/ingest POST 上述 JSON，Content-Type 为 application/json，Authorization 为 Bearer 加写令牌。
4. 整次发送预算不超过 1 秒，最多重试一次，重试保持同一个 event_id 和同一内容。401 重读发现文件；不要无限重试，不离线缓存补发旧状态。
5. 控制应答读取大小，确认 schema=3、id 为正整数、epoch 非空。不要记录或展示凭据、请求正文或原始响应。

发现文件每次服务启动都会更新，不应永久缓存端口和令牌。ACK 只表示本次运行的内存队列已接收，不保证落盘或客户端必达。

| HTTP 状态 | 处理 |
|---|---|
| 201 | 新事件已接收 |
| 200 | 去重窗口内的同 ID、同内容重复，返回原接收结果 |
| 409 | 同来源同 event_id 的内容冲突；修复插件，不修改内容后复用旧 ID |
| 400 / 413 / 415 | 非法结构、请求超限或非 JSON，修复请求 |
| 401 | 凭据失效，可在剩余预算内重读并重试一次 |
| 403 | 使用了错误权限的令牌或被来源策略拒绝，不循环重试 |

短期去重窗口结束或核心重启后，不保证旧 event_id 仍可去重。因此插件只发送当前进展，不把它当持久消息队列。

## 生成专用接入提示词

```powershell
$runtime = Join-Path $env:LOCALAPPDATA 'Programs/AgentStatusRuntime/agent-statusd.exe'
& $runtime integration-prompt
```

自定义运行目录可增加 --data-dir。输出包含可执行路径、数据目录和当前 Schema，不包含读写令牌。交给开发 Agent 后，要求其先查所用工具版本的官方扩展接口，再实现事件映射和发送；不要直接猜测回调名。

## 接入验收

使用临时 Runtime 和人工事件，不改真实会话记录。至少验证：

- 一轮开始、工具并行、自动重试、审批恢复和最终结束，operation_id 连续；工具失败不会提前终结任务。
- 消息/单步结束后继续处理时不报告 completed；真正取消和最终失败保留原意。
- 重试同一事件不重复接收，同 ID 改内容返回冲突；真实进展使用新 ID。
- 核心未运行、端口/凭据轮换和请求挂起时，插件及时返回，不影响 Agent。
- 不发送正文或工具内容，不输出 token；不使用定时 working 刷新无进展任务。
- 插件与文件事实交替时按接收顺序显示，不因依据更强而阻挡后续活动。

测试窗口可查看 origin=external、reported_basis 和原生事件名。正式客户端可以自行决定显示策略，核心不会替插件重新推断状态。
