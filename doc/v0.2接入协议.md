# v0.2 接入协议

Runtime 广播已观察的白名单事实；工作、空闲、等待及通知策略属于消费者。文件适配器只解析原生记录，外部接入程序只需把实际事件映射到本协议。Runtime 不安装、加载、执行或更新接入程序，也不修改 Agent 配置。

协议真值为 [JSON Schema Draft 2020-12](../runtime/internal/monitor/protocol/schema.json)，公共有效／无效样本见 [samples.json](../runtime/internal/monitor/protocol/samples.json)。`GET /v2/schema` 返回同一文件；根 Schema 校验输入，`$defs/fact`、`evidence`、`snapshot`、`ack`、`error` 定义输出。变更程序时同步运行公共样本测试。

## 连接、权限和请求

服务默认监听 `http://127.0.0.1:9120`，仅允许字面量 loopback IP，也支持 IPv6 `::1`。不接受主机名、HTTPS、远程 IP、URL 凭据、查询串或片段；连接地址路径只能为空或 `/`。

发现文件均在 `<data-dir>/private`：

| 文件 | 内容 | 权限 |
|---|---|---|
| `connection.json` | `{"url":"http://127.0.0.1:9120","token":"…"}` | 只读 API |
| `ingest.json` | 相同形状、独立令牌 | 单条事实写入 |

目录限制为当前用户，服务重启轮换两套令牌。每次发送／重连重新读取，避免缓存过期凭据。不要把令牌写入代码、提示词、日志、异常、URL 或输出。客户端关闭代理和自动重定向；服务拒绝带非空 `Origin` 的请求，不提供浏览器跨源写入。`producer_id` 是来源标签，不是认证身份；首版不区分各插件写权限。

所有请求使用 `Authorization: Bearer <token>`。写入为 `POST /v2/ingest`，`Content-Type: application/json`，一条 UTF-8 JSON，正文最多 16384 字节。不可提交数组、批次、未知字段、重复字段、大小写变体、显式 null／空字符串或任意原始嵌套对象；不使用的可选字段直接省略。

| HTTP | 含义 |
|---|---|
| `201` | 新事实已持久化，返回 ACK |
| `200` | 相同事件重复，返回原 ID 的 ACK |
| `400` | 格式、版本、类型、字段或关联信息无效 |
| `401` | 凭据无效；允许重读发现文件后重试一次 |
| `403` | 凭据权限错误或带 Origin |
| `409` | 同一 `(producer_id,event_id)` 对应不同内容 |
| `413`／`415` | 超过正文限制／不是 JSON Content-Type |
| `503` | 存储失败，不能视为提交成功 |

ACK 示例：`{"schema":2,"id":123,"epoch":"…","duplicate":false}`。错误为 `{"schema":2,"error":"错误代码"}`。不要把 ACK 写到 Hook stdout；它可能被原工具解释为审批或控制响应。

## 统一输入结构

| 字段 | 约束 |
|---|---|
| `schema` | 必填，整数 `2` |
| `producer_id`、`event_id` | 必填，接入实例标识／实例内唯一 ID；重试保持 ID 和内容相同 |
| `agent`、`session_id` | 必填，实际工具名及原生会话 ID；支持自定义 Agent 名称 |
| `session_namespace` | 可选，默认 `producer_id` |
| `operation_id` | 可选，本轮稳定执行 ID；报告 completed／interrupted／failed 时必填 |
| `occurred_at` | 可选，RFC3339 原生发生时间；不知道就省略 |
| `kind`、`data` | 必填，封闭事件名及对应字段对象 |
| `native_type`、`native_reason` | 可选，原生事件名和原因代码，禁止正文 |
| `reported_basis` | 可选，默认 `self_report`；仅允许 `native_event`／`inferred`／`self_report` |
| `stream_id`、`source_sequence` | 同时提供或同时省略；序号为非负整数，只在原生确有连续序号时使用 |

身份和元信息字符串上限 256 个字符，不得包含控制字符。字段具体枚举与条件以 Schema 为准。

Runtime 附加 `id`（全局递增接收序号）、`received_at`、`origin`（file／external）、`source_id`、`historical`，发现连续来源序号不匹配时另标 `sequence_gap`。发送者不能指定这些字段。外部声称 `reported_basis=native_event` 仍只是来源声明；来源永远是 external，不变成核心独立证实。

### 事件和 data 字段

下表列出允许字段；除必填项外均可省略。不得附带 `text`、`content`、`arguments`、`output` 或原始 Hook 对象。

| kind | data 字段与必填项 |
|---|---|
| `session.observed` | `surface`（cli／desktop／subagent／unknown）、`agent_version`、`parent_session_id`；持久化分支元信息 `message_id`、`parent_node_id`、`branch_changed` |
| `input.observed` | `message_id`；只表示观察到输入，不由核心改写为工作中 |
| `message.observed` | 必填 `role`（user／assistant／system／tool）；可选 `stop_reason`、`message_id`、`parent_node_id`、`has_tools`、`outcome` |
| `tool.observed` | 必填 `call_id`、`phase`（requested／started／finished）；可选 `outcome` |
| `approval.observed` | 必填 `request_id`、`phase`（requested／resolved）；可选 `decision`（allowed／denied／unknown） |
| `lifecycle.observed` | 必填 `phase`（started／ended）、`scope`（message／agent_turn／agent_run／session）；可选 `outcome` |
| `state.reported` | 必填 `state`，枚举见下方 |
| `source.heartbeat` | 空对象 `{}`；表示上报程序可工作，不代表 Agent 正忙 |

`outcome` 为 completed／interrupted／failed／unknown；started 生命周期不能带 outcome。带已知结果的 lifecycle 也必须有 operation_id。`state` 为 working／tool_activity／waiting_confirmation／idle／completed／interrupted／failed／unknown／offline。`source.health` 只由 Runtime 产生，外部不得提交。

消息结束、工具完成、审批决定、会话关闭和整轮执行结束的范围不同。明确 scope 后再表达结果；“已稳定停止”不自动等于成功完成。可靠插件应使用原生回调；让模型在回答末尾执行一次发送命令仅属于 self_report。

```json
{
  "schema": 2,
  "producer_id": "my-agent-adapter",
  "event_id": "request-42-completed",
  "agent": "my-agent",
  "session_id": "native-session-id",
  "operation_id": "request-42",
  "kind": "state.reported",
  "reported_basis": "self_report",
  "data": { "state": "completed" }
}
```

一个原生执行的所有回调必须共用 operation_id；原生没有 ID 时由接入程序在执行开始分配并保存，不能每次回调重建。工具和审批使用自己的配对 ID，不能与 operation_id 混用。

### 会话关联和来源

统一会话键为 `(agent,session_namespace,session_id)`；同一会话下的文件／外部证据仍分别保留来源。默认外部 namespace 是 producer_id，因此不会意外覆盖文件会话。

只有实际会话 ID 已确认一致，才能使用 `/v2/health` 所列文件来源 namespace 关联两种证据；该读请求必须用只读凭据。不能按工作目录、工具名或时间接近猜测关联。文件 namespace 来自规范化数据根；移动根目录可能改变关联键。

## 快照、SSE 和覆盖范围

只读接口：

| GET | 输出 |
|---|---|
| `/v2/info` | 版本、schema、mode、epoch、事件／输入／快照／幂等限制 |
| `/v2/schema` | 完整 JSON Schema |
| `/v2/health` | 数据根可达性、文件／外部来源健康、namespace、格式、文件通知状态 |
| `/v2/capabilities` | 四类文件适配器提供的事实和限制 |
| `/v2/snapshot` | 当前事实摘要及覆盖完整性 |
| `/v2/events` | text/event-stream 事实流 |

快照形状为 `{schema,epoch,revision,sessions,coverage}`；每个 session 实际是一个来源账本，包含 `{agent,session_namespace,session_id,source_id,origin,facts,coverage,incomplete_operations}`，不是推断后的业务状态。消费者按统一会话键汇总来源，不丢弃 provenance。

账本保留每种生命周期阶段、最新输入／消息、未配对工具／审批及最近相关记录、外部状态和来源健康；最多保留最近 32 个 operation、2048 条摘要事实。淘汰或来源序号缺口后 coverage 为 partial。`incomplete_operations` 列出证据不完整的 operation；`[]` 可以只表示旧历史被裁剪，仍允许解释当前完整 operation，`["*"]` 表示不能确认当前覆盖。消费者不能只检查 coverage，也不能凭不完整记录中缺少工具推断全部结束。整个快照另有 8 MiB 上限，由 `/v2/info.max_snapshot_bytes` 公布，最多包含 4096 个来源账本；响应裁剪会标记全局覆盖不完整，不能假设未列出会话不存在。它不是完整审计日志。

SSE 游标为 `epoch:revision`，通过 `Last-Event-ID` 或 `after` 查询参数提交。类型为：

- `snapshot`：首次订阅建立当前基线，不当作新完成。
- `fact`：一条已持久化事实，`id` 与游标 revision 相同。
- `reset`：epoch 不同、游标超前或超过重放窗口；替换基线并标记事件缺口，不补造通知。

保留最近 4096 条事实，约每 15 秒发注释心跳。消费者按接收序号处理和去重；`occurred_at` 不重排全局事实。没有可靠来源序号时，不能承诺发现所有丢失。文件重建／启动恢复保留 historical 标记，历史补写不发完成提醒。

外部幂等键保留最近 10 万条或七天，以先达到的淘汰条件为准；窗口外重发可能成为新事实。网络响应丢失时复用同一事件 ID；改变 ID 重试会绕过去重。首版没有离线持久队列，Agent 离线报告允许丢失。

## 发送工具和通用提示词

```text
agent-statusd report --data-dir <目录>
agent-statusd report --data-dir <目录> --best-effort
agent-statusd report --validate-only
agent-statusd integration-prompt --data-dir <目录>
```

`report` 从 stdin 读取一条 JSON，先校验，网络总预算一秒、最多重试一次。每次重读 ingest.json，401 或可重试网络错误仅在剩余预算内重试。默认成功向 stdout 写 ACK、失败非零退出；`--best-effort` 成功 stdout 为空，失败也正常退出，只向 stderr 输出脱敏代码。`--validate-only` 不需要连接文件，不做网络访问；与 best-effort 合用仍静默。

预算从读完 stdin、完成本地校验后开始；调用方必须保证 stdin 能关闭，不能把无限事件流传入一次 report。接入回调本身也要设时限，不能把 CLI 或网络异常传播为 Agent 操作失败。

`integration-prompt` 可离线生成完整接入提示词，包含可执行文件路径、数据目录和输入 Schema，不包含令牌。要求接入 Agent 检查实际工具版本和官方机制，输出映射、代码、配置差异、专用 Runtime 验证命令、限制和卸载说明。Runtime 本身不执行生成代码。

示例：[PowerShell 7](../examples/report-state.ps1)、[Python 标准库](../examples/report_state.py)。两者支持 CLI 和直接 HTTP，共用一次 event_id／payload，预算一秒，最多两个发送尝试，不读取或打印原始 Hook payload。直接 HTTP 禁用代理／重定向，每次尝试重新读取写连接文件；失败只向 stderr 写 report_unavailable，正常退出。CLI 路径通过参数传递，不构造 shell 命令字符串。

示例固定报告 self_report。生产插件应按实际证据选择 kind 和依据，不能仅换字段就自称已验证原生成功。模型、插件和核心之间的可信度边界保留在事件中，而不是依赖调用者填写的名称。

原生事件要按实际工具版本核实。例如 [Pi 官方 JSON 事件文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/json.md) 中，`agent_end` 是底层执行结束，后面仍可能有重试、恢复或排队工作；`agent_settled` 才表示没有剩余自动工作，但仍不能忽略中断／失败结果而宣称成功。[Claude 官方 Hook 文档](https://code.claude.com/docs/en/hooks) 的 Stop／SubagentStop 可以通过阻断或额外上下文继续执行，API 错误另有 StopFailure。接入程序必须保留这些范围和结果差异，不可只按事件名称中的 end／Stop 映射 completed。

## 客户端解释规则

测试窗口使用独立 `default-v1` 规则；它是消费者实现，不是 Runtime 状态 API。

- 输入／明确开始推断工作；工具与审批证据分别保持配对，不把单个工具结束当作任务结束。
- Codex／DSH agent_turn／agent_run 的明确 completed 可以提醒成功；interrupted／failed 与完成区分。
- Claude 正常 end_turn／stop_sequence、Pi 正常 stop 且没有未配对工具／审批、覆盖完整时，可推断空闲。异常或截断不能套用正常结束规则。
- 外部完成显示“任务完成（外部报告）”，无论发送者声明 native_event 还是 self_report，都保留外部身份。
- 两分钟后未确认活动证据过期；心跳不延长 Agent 工作证据。核心事实不受此规则影响。
- 同一统一会话、operation 和 scope 的结束只提醒一次；首次快照、重置、historical 不生成新完成提醒。无法确证关联的来源不强行去重合并。

其他上位机可读取同样事实实现不同超时、来源选择和通知策略。正常回合结束只说明执行边界，不代表任务成果已满足用户验收。

## 迁移与回滚

v0.2 不保留 `/v1` 状态接口；Runtime、CLI 和窗口一起更新。旧客户端收到 protocol_upgrade_required，必须换新版。

1. 记录现有启动参数、数据目录、监听地址和根目录；退出窗口。保留 v0.1 Runtime／窗口二进制到单独版本目录。
2. 校验后台 PID 的可执行文件路径及启动参数，停止该 Runtime 并等待退出。不要只按进程名停止其他数据目录的实例，也不要覆盖仍在运行的二进制。
3. 停止后备份整个 private 目录（包括存在的 SQLite WAL／SHM）；其中含凭据，按当前用户权限保护，不对外分享。不要在运行中仅复制 state.sqlite。
4. 成对替换程序，用原参数启动 v0.2，再开新窗口。它使用独立 `private/facts-v2.sqlite`；原 `state.sqlite` 不删除、不导入，也不将旧推断冒充事实。原数据目录租约防止两版同时运行。
5. 首次文件扫描建立历史基线；检查 version=0.2.0、schema=2、status／doctor／watch、窗口会话数量和诊断。重启后写入与只读令牌都改变，接入程序必须重读文件。

回滚：退出新版窗口，校验并停止 v0.2、等待退出，恢复原 Runtime／窗口及启动参数，继续使用保留的 state.sqlite。保留 facts-v2.sqlite 便于后续升级；旧版不会读取它。外部上报接口随回滚不可用，best-effort 发送器应正常放弃，不能尝试自启动服务。回滚后旧库可能尚未见到新日志，旧版按其恢复规则读取；不能声称把 v2 外部事实自动转成 v1 状态。

构建和测试不等于正式切换。开发／验收使用独立数据目录、临时 Runtime、构造日志；不向真实 Agent 记录注入数据、不安装 Hook。验收至少覆盖凭据隔离、重复／冲突、服务离线、重启轮换、SSE 缺口、历史不通知，以及“构造上报 → 持久化 → SSE → 窗口”的实际链路。
