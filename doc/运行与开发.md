# 运行与开发

本页集中记录当前 0.3.0 / schema 3 的安装、参数、构建和发布方法。功能边界见 [README](../README.md)，通信字段见 [接入协议](接入协议.md)。

## 安装、更新和维护

Windows x64 用户从 [Releases](https://github.com/aoang-git/Agent_Status_Runtime/releases) 下载 `agent-status-setup.exe`，双击安装。安装器内嵌核心，无需安装 Go、.NET 或使用管理员权限；系统策略禁止任务注册时会明确失败，不自动提权。

| 位置 | 用途 |
|---|---|
| `%LOCALAPPDATA%/Programs/AgentStatusRuntime` | 核心可执行文件和部署标识，需要保留 |
| `%APPDATA%/AgentStatusRuntime` | 当前用户的运行目录 |
| 运行目录的 `private/connection.json` | 本机只读客户端发现地址和读令牌 |
| 运行目录的 `private/ingest.json` | 插件发现地址和独立写令牌 |
| 运行目录的 `private/service.log` 及轮转文件 | 服务及采集故障诊断，最多两份各 1 MiB |

安装器注册当前用户、最低权限的计划任务：登录启动、每分钟补启动、重复实例忽略、允许电池运行、无执行时限。需要该用户处于登录状态；这不是登录前运行的系统服务。

运行新版安装器会原位替换并启动核心、检查健康，无需先卸载。成功后安装器可以删除。更新会中断当前广播，新的服务实例重新生成 epoch 和令牌，不恢复旧任务；客户端需重新发现并订阅。目前没有自动下载更新功能。

维护命令只针对默认安装：

```powershell
$runtime = Join-Path $env:LOCALAPPDATA 'Programs/AgentStatusRuntime/agent-statusd.exe'
& $runtime stop
& $runtime start
& $runtime restart
& $runtime uninstall
```

这些命令分别使用，不必连续执行。stop 先禁用补启动，start 重新启用；uninstall 移除自身任务及程序，保留运行目录，不修改 Agent 数据。维护命令不接受额外参数。

## CLI 与参数

以下示例在仓库根目录执行。手动运行不注册自启动：

```powershell
./bin/agent-statusd.exe serve --data-dir ./.runtime/live
./bin/agent-statusd.exe doctor --data-dir ./.runtime/live
./bin/agent-statusd.exe watch --data-dir ./.runtime/live
./bin/agent-statusd.exe status --data-dir ./.runtime/live
```

| 命令 | 行为 |
|---|---|
| `version` | 输出核心版本 |
| `serve` | 运行采集和 HTTP/SSE 服务 |
| `doctor` | 查询当前采集健康 |
| `watch` | 订阅连接建立后的新增事实 |
| `status` | 输出近期诊断记录，不是恢复型状态快照 |
| `report` | 从 stdin 读取一条标准状态 JSON，上报给已运行服务 |
| `integration-prompt` | 输出包含本机路径和 Schema 的插件生成提示词 |

| 参数 | 适用范围及默认值 |
|---|---|
| `--data-dir PATH` | 默认当前用户配置目录下 AgentStatusRuntime；Windows 为 APPDATA，Linux/macOS 遵循 Go 的用户配置目录 |
| `--listen IP:PORT` | serve 默认 127.0.0.1:9120，仅字面量回环 IP；默认端口占用时选空闲端口，显式指定则占用即失败，端口 0 表示动态分配 |
| `--root AGENT=PATH` | serve 可重复指定 codex、claude、deepseek、pi；一旦指定即替代自动根目录列表 |
| `--interval DURATION` | serve 已知来源兜底检查，默认 5s，至少 250ms；新目录定期发现为 30s，文件事件合并为 250ms |
| `--background` | serve 将服务诊断写入有界日志；Windows 后台运行不附着控制台 |
| `--validate-only` | report 仅校验输入，不连接服务 |
| `--best-effort` | report 成功不输出 ACK，失败只输出脱敏错误代码并正常退出；插件仍需自行设置调用时限 |

每个运行目录通过操作系统锁限制一个核心实例。监听地址不能直接开放到局域网，也不接受浏览器跨域请求。

## 默认来源目录

| Agent | 默认目录及覆盖变量 |
|---|---|
| Codex | `CODEX_HOME/sessions`；未设置时为 `~/.codex/sessions` |
| Claude Code | `CLAUDE_CONFIG_DIR/projects`；未设置时为 `~/.claude/projects` |
| DeepSeek DSH | `DSH_HOME/sessions`；未设置时为 `~/.dsh/sessions` |
| Pi | `PI_CODING_AGENT_SESSION_DIR`；未设置时为 `~/.pi/agent/sessions` |

缺少目录时待机，之后发现目录再接入。仅读取 Agent 记录，不执行终端配置脚本。已有记录可能被读取以建立后续解析所需上下文，但不会作为新活动广播；大量历史文件仍可能增加基线和目录扫描开销。

## 测试窗口

```powershell
./bin/agent-status-test.exe
./bin/agent-status-test.exe --data-dir ./.runtime/live
```

默认优先使用已安装服务的用户运行目录；没有用户连接文件时，才回退到带有当前格式连接文件的项目 `.runtime/live`。显式参数或手动选择目录始终优先。旧连接文件不会被兼容读取。

窗口的会话、事实/通知和采集诊断仅用于开发。顶部只维护最新一个显示轮次；启动、重连和 gap 清除顶部，不从 recent 恢复。工作、工具和审批切换保持同轮计时；明确结束或推断结束后停止，只有结束事件时不虚构开始时间。

文件事实的正常消息结束后，须没有待处理工具、审批或已知证据缺口，静默 3 秒才提前推断。普通活动无有效进展 5 分钟、审批等待 30 分钟后超时结束；健康、心跳和未知不刷新有效活动时间。结束通知 10 秒后清除，推断不撤回，后续活动重新开轮。详细解释案例见 [interpretation.json](../runtime/internal/monitor/protocol/interpretation.json)。

## 构建与验证

Windows 开发环境需要 Go 1.26+、.NET 10 SDK 和 PowerShell 7。构建脚本优先使用仓库 `.tools/go` 中的 Go，否则使用 PATH。

```powershell
./scripts/build.ps1 -Test
./scripts/build-test-window.ps1 -Test
```

先构建核心，再测试窗口，确保窗口的真实 Runtime 集成测试有可执行文件可用。核心脚本执行 Go 全量测试和 go vet，构建 Windows 核心及安装器，并交叉构建 Linux amd64、macOS arm64；窗口脚本执行 .NET 测试并发布 Windows x64 自包含单文件。Linux/macOS 可在 runtime 下用 `go build ./cmd/agent-statusd` 手动构建。

单独验证：

```powershell
Push-Location runtime
go test ./...
go vet ./...
Pop-Location
dotnet test manager/test-window/Tests/Tests.csproj
```

输出位于 bin，每个程序及平台只保留最新版。构建会核验并关闭占用输出的本项目进程，原位重试并恢复此前实例；不修改 Agent 配置或记录。持续长稳测试期间不要覆盖其核心程序。

`scripts/test-install.ps1` 使用隔离目录和独立计划任务测试安装、重装、启停、异常退出恢复和卸载，不覆盖用户安装。长稳验证方法见 [性能评估](性能评估.md)。

## GitHub Releases

[发布工作流](../.github/workflows/release.yml) 在 GitHub 云端 Windows Runner 执行，不上传本机 bin。运行 Go 测试、go vet 和窗口测试后重新构建，附件仅发布：

- `agent-status-setup.exe`：内嵌同次构建核心的 Windows x64 安装器。
- `agent-status-test.exe`：Windows x64 自包含测试窗口。
- `SHA256SUMS.txt`：上述两项的 SHA-256 校验值。

发布顺序：先更新 `runtime/internal/monitor/model.go` 的 Version、提交并推送代码，再在对应提交创建和推送版本标签。标签去掉 v 后必须与 Version 完全一致。例如源码版本为 0.3.1 时：

```powershell
git tag -a v0.3.1 -m "Release v0.3.1"
git push origin v0.3.1
```

`v0.3.1-rc.1` 等后缀版本标记为预发布，不设为 Latest；正式版本交给 GitHub 默认规则判断。工作流使用内置 GITHUB_TOKEN 的 contents:write 权限，无需个人访问令牌，但仓库必须允许 Actions 运行。

若新标签未触发，可到 **Actions → Release Windows executables → Run workflow**，分支选择 main，tag 填已有标签。手动入口必须已推送到默认分支；构建仍检出所填标签的源码。手动和自动发布同版串行处理，无需删除或移动标签。

已存在的 Release 不覆盖。构建失败可重跑；上传中断若留下未发布草稿，先检查并删除该草稿，再重跑。正式发布后修复使用新版本。只有源码 zip/tar.gz 不代表构建成功，以工作流日志和 exe 附件为准。
